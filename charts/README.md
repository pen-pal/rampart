# Rampart Helm Chart

A Helm chart for deploying [Rampart](https://github.com/pen-pal/rampart) — the
Rust-based status-page / incident service — onto Kubernetes.

## TL;DR

```bash
# Bring your own Postgres (recommended)
helm install rampart ./charts/rampart \
  --set externalDatabase.url=postgres://user:pass@db.internal:5432/rampart

# Evaluation only — spins up an embedded Postgres StatefulSet
helm install rampart ./charts/rampart --set postgres.embedded=true
```

## Prerequisites

- Kubernetes 1.24+
- Helm 3.10+
- A Postgres 14+ database the cluster can reach (unless you enable the embedded
  StatefulSet for evaluation)

## Install

```bash
helm install rampart ./charts/rampart \
  --namespace rampart --create-namespace \
  --set externalDatabase.url=postgres://user:pass@db.internal:5432/rampart
```

The `SESSION_KEY` is generated by the chart on first install and stored in the
release Secret. Subsequent upgrades will reuse the existing value via
`lookup` so sessions are not invalidated. Override it explicitly with
`--set sessionKey=...` if you want to pin it.

## Upgrade

```bash
helm upgrade rampart ./charts/rampart \
  --namespace rampart \
  --reuse-values \
  --set image.tag=0.3.0
```

Or, to pick up new chart-side defaults while keeping your overrides in a file:

```bash
helm upgrade rampart ./charts/rampart \
  --namespace rampart \
  -f my-values.yaml
```

A `checksum/config` and `checksum/secret` annotation on the Pod spec ensures
that ConfigMap / Secret changes trigger a rolling restart.

## Uninstall

```bash
helm uninstall rampart --namespace rampart
```

PVCs from the embedded Postgres StatefulSet are intentionally **not** deleted by
`helm uninstall` — remove them explicitly if you want to drop the data:

```bash
kubectl -n rampart delete pvc -l app.kubernetes.io/component=postgres
```

## Embedded Postgres caveat

Setting `postgres.embedded=true` provisions a single-replica Postgres
StatefulSet inside the release. This is convenient for kicking the tires but is
**explicitly evaluation-only**:

- No HA, no PITR, no automated backups.
- A single PVC — losing the node losing the volume loses the data.
- Credentials live in a chart-managed Secret with a generated password.

Production deployments should set `postgres.embedded=false` (the default) and
point `externalDatabase.url` at a managed Postgres such as RDS, Cloud SQL, Neon
or Supabase.

## Troubleshooting

- `externalDatabase.url is required when postgres.embedded=false` — set
  `--set externalDatabase.url=...` or enable the embedded StatefulSet.
- Pod stuck `CrashLoopBackOff` — check `kubectl logs`. The most common cause is
  `DATABASE_URL` pointing at a Postgres the pod cannot reach (NetworkPolicy,
  security group, wrong host).
- `readOnlyRootFilesystem` denial — the chart mounts an `emptyDir` at `/tmp`
  for scratch. If the binary writes elsewhere, add another `emptyDir` mount via
  a custom values override.
